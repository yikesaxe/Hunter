Hunter

NYC apartment search — scrape, score, recommend

Next.js app + BullMQ scraper workers + PostgreSQL. AI-powered natural-language search, recommendation feed, listing detail pages with AI analysis, map view, and multi-source dedup.

← → or buttons to navigate · ~10 min

Backend & data

AI

Architecture

Two subsystems sharing one PostgreSQL database.

1. Next.js app — Listings UI, AI search API, listing/detail APIs, runs monitor, onboarding, events.
2. Scraper workers — Single process: crawl-index, scrape-listing, refresh, geocode, analyze-text, analyze-photos + scheduler. Same DB + Redis.

Deploy: one Railway service (Next + worker) or split.

Data model (core)

CanonicalUnit — One physical apartment; deduped across sources. activePostingsCount, bestRentGross, lastMatchScore.

NormalizedListing — One posting (one source URL). active → stale/removed. contentHash, consecutiveMisses/Fails.

CrawlJob (per device × source × searchUrlHash) + CrawlRun (target, discovered, scraped; CrawlRunSeen for miss-pass).

Data model (AI & raw)

AI analysis

ListingAnalysis — summary, priceTier, redFlags, brokerSpeak; photoFlags, overallPhotoScore; subwayStations, complaints311, nearbyAmenities; neighborhoodMedian, pricePercentile. *AnalyzedAt + hash per type.

Raw & events

RawListing — Append-only scrape JSON. ChangeLog — field-level changes. Event — impression, click, save, hide, outbound. Device / Preference / DeviceProfile for onboarding and recommendations.

Scraper pipeline

crawl-index — Fetch search page, extract URLs, enqueue scrape-listing, paginate, miss-pass.

scrape-listing — Fetch listing page → parseListing() → upsert NormalizedListing, RawListing; enqueue refresh, geocode, analyze-text, analyze-photos.

refresh — Re-fetch for price/status. geocode — lat/lon. analyze-text / analyze-photos — Claude summary, price tier, red flags, photo score.

Fetch & anti-bot

  • Tier 1 — Plain HTTP (rotating UA, cookie jar, rate limit).
  • Rebrowser-playwright — Headed browser, anti-detection, CAPTCHA, sessions.
  • FlareSolverr — Cloudflare bypass (StreetEasy, Leasebreak, etc.).
  • Firecrawl — Last resort API.

Blocked pages → scraper/debug/. StreetEasy search may need __NEXT_DATA__ or browser render.

App: Listings & AI search

Listings page

Search — Source filter, keyword, infinite scroll. Recommended — /api/listings?mode=recommended (device prefs + scoring).

AI search

Natural language → POST /api/ai-search. Claude parses → prefs (neighborhoods, beds, price, amenities). Score top 400, take top 20, Claude reranks to top 10; return + summary. Optionally trigger StreetEasy crawl; frontend “Hunter is searching…” and auto-refresh ~35s.

App: Detail page & map

Listing detail

/listings/[id] — PhotoGallery, Description, Amenities, LocationMap. Subway (MTA colors), scrapedExtras. AI: summary, price tier, red flags, photo score. Outbound tracking.

Map & UX

MapLibre map on list view; pins + hover sync with cards. Onboarding → Preference. Save/hide, filters (neighborhood, beds, baths, price, amenities), sort (match / value / space). Badges: No Fee, Below Market, New, AI Pick.

APIs

  • GET /api/listings — Search (?q, ?source, ?minPrice, ?maxPrice, ?neighborhood, ?limit). ?mode=recommended.
  • POST /api/ai-search — { prompt } → listings, summary, scrapeTriggered, runId.
  • GET /api/listings/[id] — Single listing.
  • GET /api/runs, /api/sources, /api/crawl-jobs — Crawl monitoring.
  • POST /api/events — impression, click, save, hide, outbound.
  • /api/prefs, /api/profile — Device preferences and recommendation weights.

Scoring & recommendations

lib/recs/score.ts — Prefs: minPrice, maxPrice, beds, neighborhoods, amenities. Hard filters then soft score: budget fit, beds, neighborhood, amenities, recency, completeness. Optional DeviceProfile weights.

Recommendations: filter by Preference, score with profile, sort, top N. AI search: same scoring → top 20, then Claude rerank → top 10.
